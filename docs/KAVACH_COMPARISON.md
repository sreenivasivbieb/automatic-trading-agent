# Kavach reference and AEGIS connections

The supplied `kavach-main/` folder was inspected read-only and retained locally. It is excluded from Git and Docker contexts; its keys, runtime files and published addresses are not adopted as AEGIS configuration. No dependencies were installed in that reference. JavaScript syntax checks and contract source/ABI/runtime inspection were performed; its npm/Hardhat suites were not run.

| Connection           | Kavach implementation examined                                                                         | AEGIS implementation                                                                                                                     |
| -------------------- | ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Browser/backend      | Local Node HTTP/SSE server and browser controls                                                        | Existing authenticated FastAPI session/CSRF boundary, cached state and React AEGIS workspace                                             |
| State/execution      | Engine selects PaperVault or ChainVault                                                                | Single-writer runtime → software policy → paper gateway → atomic SQLite; separate explicit hot-key gateway for registered real contracts |
| Network              | Agent imports mainnet token constants and chain 177; changing RPC alone does not select testnet tokens | Per-chain verified registry, code/chain checks and distinct 18/6-decimal USDT handling                                                   |
| DEX                  | V3 pool reads and SwapRouter02                                                                         | Typed connector with fresh canonical snapshots, real QuoterV2 routes, proxy pins and no read-client broadcast method                     |
| Paper failure        | An estimated fill path exists after quote failure                                                      | Failed verified quotes block fills; no estimated-price fallback                                                                          |
| Conversational close | Local chat can directly close positions                                                                | Expiring one-use holdings-bound preview; human confirmation outside model tools                                                          |
| Safety keeper        | Separate keeper/dead-man process; keeper reward in reference contract                                  | Separate contract-triggered safety keeper, distinct commitment domain and no payout or proceeds to caller                                |
| Decisions            | Decision/event anchoring in reference vault                                                            | Exact-byte earlier-block commitment → typed vault action → canonical reconciliation → unchanged reveal, with a separate verifier         |
| Demonstration        | Recorded/static demo frames are included                                                               | Actual live-data paper HTTP run and browser screenshots, labeled fixture interaction tests, separate local signed-fork evidence          |

The supplied testnet vault `0x560295F23c699c97C35368B34FcFDFAD83780A2D` was checked in this session against actual RPC bytecode, source compilation/immutable slots and supplied receipts. The reference's agent-open receipt and dead-man-close receipt are real testnet activity, not AEGIS deployments. The inspected close caller was the owner acting as keeper; it does not establish an independently operated keeper service. This analysis does not constitute a security audit or a profitability result.

The useful reusable design is the separation between monitoring, execution state and an independently available safety exit. AEGIS implements that separation within its existing Python/React stack and fixed-recipient Guard. It does not import Kavach's raw HTTP control server, key handling, fallback paper fills, keeper rewards or recorded performance as AEGIS evidence. Public AEGIS funding and deployment remain pending the user's actual owner address and separately funded accounts.
